# SPLIT SIGNAL

**4人、2つの身体、全3ラウンド。** 2人で1体のロボットを操作する、2対2の対戦FPSです。同じ機体の2人が視覚情報と操作権を分け合います。HTML / CSS / JavaScriptとCanvasによる疑似3Dで動作し、ビルドやゲーム用サーバーは不要。GitHub Pagesに公開できます。

## ゲームの独創性

「見える人が操作できない」という相互依存を、1体のキャラクターの中に作ります。

| 役割 | 見えるもの | 操作 | 相棒に頼ること |
| --- | --- | --- | --- |
| 下半身 / SEEKER | 相手機体、回復コア、壁の簡単な輪郭 | WASDで視線基準の移動、コアの自動回収 | 安全な道、敵への照準、攻撃 |
| 上半身 / ARCHITECT | 地形の詳細、危険な床、自分の位置を示す地図 | マウスまたは矢印キーで首と照準を上下左右へ、クリックまたはSpaceで射撃、Gでピン | 相手機体やコアの位置、身体の進路 |

A機・B機に各2人が乗り、チーム同士で戦います。相手機体は下半身役にだけ見えます。上半身役の画面・地図には相手の位置も回復コアも表示されません。

**移動は視線基準です。** 上半身役が視点を回すと、下半身役のWの前進方向も変わります。A/Dは視線に対する左右移動、Sは後退。上下の照準角度は地上の移動速度に影響しません。Z/Cによる独立した身体旋回は廃止しました。

首は左右360°に制限なく回転し、上下は±60°。上下の照準は射撃にも反映され、頭上や足元を狙うと外れます。人型モデルの肩・肘・股関節・膝は歩行に合わせて動き、首と射撃側の腕は照準に追従します。右下の自機モデルで姿勢を確認できます。描画はCanvasによる疑似3D、命中判定は機体の幅と高さによる簡易判定で、部位別ダメージはありません。

## 対戦ルール

- **全3ラウンド**を必ず実施。2勝先取で打ち切らず、3ラウンド終了時の勝利数が多いチームの総合勝利。同点なら総合引き分け。
- 各ラウンド90秒、両機100HPから開始。射撃1発25ダメージ、連射間隔0.3秒。壁越しには命中しません。
- 相手のHPを0にするとそのラウンドの勝利。時間切れでは画面に表示される残りHP（小数切り上げ）が多い側の勝利。同じHPや同時撃破は引き分けで、どちらにも勝利数を加算しません。
- 回復コアに触れると30HP回復（最大100）。HP満タンでは消費しません。赤い危険な床では毎秒14ダメージ。敵ドローン・脱出・救助は対戦にはありません。
- ラウンド間は5秒の結果表示。開始位置を交代し、HP・回復コア・弾の表示・合図をリセットして自動的に次ラウンドへ進みます。
- 3ラウンド後はホストの「もう一度3ラウンド対戦」でスコアをリセットして再戦。途中で誰かが抜けた場合は、ラウンド間の待ち時間も含めて一時停止します。

独創性の説明例：「一般的な協力ゲームは各プレイヤーが自分の身体を操作する。本作では認識と行動を別の人に割り当てることで、何を見たかを言葉にすること自体をゲームの操作にしている。」類似作品が存在しないことを保証するものではありません。

## すぐに試す

```sh
npm start
```

または `python3 -m http.server 8080 --bind 127.0.0.1` を実行し、<http://localhost:8080> を開きます。Python 3が必要です。実行時に `npm install` は不要です。ES Modulesを使うため、`index.html` を直接ダブルクリックする方法では動作しません。

「まずは、ひとりで試す」の矢印から練習できます。**Tabで上半身と下半身を切り替えます。自動操作の相棒はいません。** 上半身で周囲を見て向きを決め、下半身に切り替えてWASDで移動してください。1人練習は従来の脱出ルールを残しています。6分以内にコア4個を回収し、A機が北東の出口に入るとクリア。対戦は4人接続時に遊べます。

## 4人で遊ぶ

1. 全員が同じ公開URLをPCで開く。チームごとに音声通話をつなぐか、相棒と声を掛け合う。
2. 1人が名前を入力して「ルームをつくる」を押す。
3. 「招待をコピー」でURLを共有。ほかの3人はURLを開いて「参加」、または6桁のコードを入力。
4. A機の下半身・上半身、B機の下半身・上半身の4枠が埋まったら、ホストが「3ラウンドの対戦を開始」を押す。
5. 上半身は **Gキーまたはピンボタン** で照準先にピン。開始直後から使用でき、再使用まで15秒。ピンは6秒間、自分と相棒に位置・距離を表示。画面外では端に方向を表示します。Q / Eの定型メッセージも利用可能。Escでマウスを解放。

ピンは照準が当たる壁・床・天井への位置指定で、敵を自動検出・追尾しません。上半身には敵が見えないルールを維持しているため、相棒の報告を聞いて注意地点を指定します。ホストが役割・再使用時間を検証し、ラウンド開始時にリセット。待ち時間はゲーム進行中のみ減り、接続待ちでは停止します。

参加時は空いている役割に自動配置されます。ロビーでは空席へ変更できます。ホスト以外の切断中はゲームが一時停止し、参加者が補充され4人そろうと再開します。再参加者は空席に入ります。**ホストが退出・再読み込みするとルームは終了**し、ホスト移譲やセーブはありません。ホストはゲームのタブを前面に保ってください。バックグラウンドではブラウザの描画頻度制限によりゲーム進行が遅くなります。

スマートフォンでも説明画面は閲覧できますが、ゲーム操作はPCのキーボード・マウス向けです。ゲーム内の音声通話、タッチ操作は未実装です。

## GitHub Pagesに公開

このリポジトリのルートがそのまま公開用ファイルです。`vendor/` と `network-config.js` を含めてGitHubへpushしてください。

1. GitHubのリポジトリで **Settings → Pages** を開く。
2. **Build and deployment → Source → Deploy from a branch** を選ぶ。
3. pushしたブランチ（例：`main`）と **`/ (root)`** を選び、Save。
4. デプロイ完了後、表示されるURLを4人で開く。

リポジトリが `Nag1t0727/fps_roleplay` の場合、通常の公開先は `https://nag1t0727.github.io/fps_roleplay/` です。これは想定URLであり、このプロトタイプ作成時点で公開されたことを意味しません。カスタムドメイン等によってURLは変わります。

参考：[GitHub Pages公式手順](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)

## P2P通信の仕組みと制約

HTMLとCSSだけでは通信できないため、JavaScriptのWebRTC DataChannelをPeerJS 1.5.5経由で使用しています。接続を取り持つシグナリングにはPeerJS Cloudを利用します。ゲームの計算はホストのブラウザが担当し、3人のブラウザと直接データを交換します。独自のゲームサーバーは不要ですが、完全に外部サーバー不要という意味ではありません。

- ホストがシミュレーションを進め、約20回/秒で状態を配信。各クライアントは入力を送信する。
- ホストは接続ごとの役割を管理し、他の役割の操作を適用しない。入力値を制限し、400ms以上更新がない入力は解除する。
- 壁・敵・コアなどの状態は各ブラウザへ配信し、役割に応じて描画を変える。改造クライアントへのチート対策や秘密情報の保護は対象外。
- 学校・企業のファイアウォールやNATの種類によってWebRTCの直接接続ができない場合がある。別回線で試すか、別途TURNサーバーを用意する必要がある。PeerJS 1.5.5の既定設定には終了済みのTURNサービスが含まれるため、本作では明示的なSTUN設定で置き換える。有効なTURN中継は初期状態では未設定。
- HTTPSのGitHub Pagesまたはlocalhostで実行。画面やマイクの権限は不要。音声通話は別サービスを利用する。
- PeerJSの配布ファイルは`vendor/`に同梱し、MITライセンスを添付。練習モードは通信サーバーを使わない。Google Fontsの取得に失敗しても代替フォントで動作。
- 視線基準の移動・ピン対応版は通信プロトコルv5を使用。以前の版のルームには接続できないため、全員がページを再読み込みしてから新しいルームを作成する。

### 接続エラーと今回の修正

シグナリング切断後にホストが再登録されない不具合を修正。同じコード・参加者・役割・既存の通信を保って最大6回、自動再接続します。参加者側もホストが一時的に見つからない場合は計4回まで照会します。サーバー接続には20秒、その後のプレイヤー間接続には別途45秒の待ち時間を設けました（以前は全体で18秒）。再接続で切断済みのゲーム通信が自動復活するわけではなく、DataChannelが切れた参加者はロビーから再参加します。

| 表示コード | 意味・確認すること |
| --- | --- |
| `ROOM_NOT_FOUND` | サーバーにホストが登録されていない。コード違い、ホストの退出・再読み込み・回線切断、古い版の利用を確認。全員で更新し、ホストが新しいルームと招待URLを作る。 |
| `SIGNALING_TIMEOUT` / `SIGNALING_ERROR` | 接続サーバーとの通信に失敗。インターネット接続・回線制限・PeerJS Cloudの状態を確認。 |
| `P2P_TIMEOUT` / `P2P_FAILED` | サーバーへの接続後、ホストとの通信が成立しない。ホストのタブを前面に保ち、別回線で試す。NATやファイアウォールによる制限にはTURN中継が必要。 |
| `SIGNALING_LOST` | 自動再接続も失敗。既存のP2P通信は継続できるが新規参加はできない。回線復帰後にタブへ戻ると再試行。 |
| `TURN_CONFIG` | 以下の中継設定取得に失敗。取得先、JSON形式、CORSを確認。 |

公開版への反映にはGitHubへpushしてPagesのデプロイを待つ必要があります。デプロイ後に全員が再読み込みし、ホストが新しいルームを作成してください。招待URLと変更したJavaScriptには更新識別子を付け、古いキャッシュを利用しにくくしています。

### TURN中継を利用する場合

`network-config.js` の `peerOptions` で独自のPeerServer / STUN / TURNを設定できます。従来の `globalThis.SPLIT_SIGNAL_PEER_OPTIONS` も利用できます。**終了済みTURNの参照を除去しただけでは、直接接続できない回線同士はつながりません。** 有効なTURNサービスまたは自前のTURNサーバーが必要です。

短期認証情報を発行するHTTPSエンドポイントがある場合は、`iceServersUrl` にその公開URLを設定します。ホスト・参加者それぞれが接続前に取得し、STUN設定に追加します。応答は下記の形か `RTCIceServer` の配列で、サイトのオリジンからのCORSアクセスを許可してください。

```json
{"iceServers":[{"urls":["turns:YOUR_SERVER:443"],"username":"TEMPORARY_USERNAME","credential":"TEMPORARY_PASSWORD"}]}
```

発行用のAPIキーはエンドポイント側のサーバーで保管します。GitHub Pagesの公開ファイルや取得URLへ秘密鍵・管理APIキー・TURNの長期認証情報を埋め込まないでください。エンドポイント・TURNサービスの運用は別途必要で、本リポジトリには含みません。設定取得失敗時は `TURN_CONFIG` を表示します。

参考：[PeerJS接続方法](https://peerjs.com/client/getting-started)、[シグナリングとNAT/TURNの制約](https://peerjs.com/client/faq)、[PeerJSの無料TURN終了告知](https://github.com/orgs/peers/discussions/1172)

## 自動発動アイテム

対戦マップには既存の回復コア4個（修理パック）と、シールド・加速バッテリー・視界リンク・スキャンパルスを各2個配置。練習にはこれら4種各2個と修理パック2個を追加し、脱出用コア4個は別のままです。下半身役が触れると機体の2人に即時発動します。

| 種類 | 効果 |
| --- | --- |
| 修理パック | HPを30回復、上限100。満タン時は拾わず残す。 |
| シールド | 8秒以内に受ける敵の攻撃を1回無効化。危険な床には無効。 |
| 加速バッテリー | 6秒間、移動速度1.3倍。 |
| 視界リンク | 3秒間、両方の役割に敵・アイテム・地形を表示。壁越しに敵本体は見えない。 |
| スキャンパルス | 取得時点の敵位置を3秒間、機体の2人にマーカー表示。壁越しにも表示するが自動追尾しない。Gのピンとは独立。 |

効果と残り時間は右側に表示。同じ効果の再取得は時間を更新し、倍率・防御回数は重ねません。ラウンド中のアイテム再出現はなく、次ラウンド・再戦で全配置と効果をリセット。効果時間はホストのゲーム時間に従い、接続待ち中は停止します。同時取得は近い機体を優先し、完全な同距離なら残します。練習のドローン攻撃は0.8秒ごとに8ダメージで、シールドはその1回を防ぎます。

### 入室タイムアウトの切り分け

参加時に通信経路が開くと、入室情報を再要求します。応答待ちの間は1.5秒間隔で再要求し、入室完了またはキャンセルで停止します。

- `P2P_TIMEOUT`：通信経路が未成立。ICE状態とTURN設定の有無を併記します。TURN設定ありでも中継の稼働や到達性を保証するものではありません。
- `JOIN_TIMEOUT`：通信経路は成立したが入室情報が届かない状態。全員のページ更新とルーム再作成を確認します。
- TURN未設定のままでは、直接接続を制限する回線でのタイムアウトは解消できません。
