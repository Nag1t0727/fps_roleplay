# SPLIT SIGNAL

**4人、2つの身体、異なる世界。** 視覚情報と操作権を分け合う協力型FPSのプロトタイプです。HTML / CSS / JavaScriptとCanvasによる疑似3Dで動作し、ビルドやゲーム用サーバーは不要。GitHub Pagesに公開できます。

## ゲームの独創性

「見える人が操作できない」という相互依存を、1体のキャラクターの中に作ります。

| 役割 | 見えるもの | 操作 | 相棒に頼ること |
| --- | --- | --- | --- |
| 下半身 / SEEKER | 敵、エネルギーコア、壁の簡単な輪郭 | WASDで前後・左右に移動、コアの自動回収 | 安全な道、旋回、攻撃 |
| 上半身 / ARCHITECT | 地形の詳細、危険な床、地図、出口 | マウスまたは左右キーで旋回、クリックまたはSpaceで射撃 | 敵やコアの位置、移動 |

A機・B機に各2人が乗ります。2組は対戦ではなく協力し、6分以内に4個のコアを回収して、2体とも北東の出口に入るとクリア。HPが0になった機体には、生きている機体が2マス以内で4秒待つと救助できます。全機停止か時間切れで失敗です。

独創性の説明例：「一般的な協力ゲームは各プレイヤーが自分の身体を操作する。本作では認識と行動を別の人に割り当てることで、何を見たかを言葉にすること自体をゲームの操作にしている。」類似作品が存在しないことを保証するものではありません。

## すぐに試す

```sh
npm start
```

または `python3 -m http.server 8080 --bind 127.0.0.1` を実行し、<http://localhost:8080> を開きます。Python 3が必要です。実行時に `npm install` は不要です。ES Modulesを使うため、`index.html` を直接ダブルクリックする方法では動作しません。

「まずは、ひとりで試す」の矢印から練習できます。**Tabで上半身と下半身を切り替えます。自動操作の相棒はいません。** 上半身で向きを決め、下半身で移動し、敵を見つけたら上半身に切り替えて射撃してください。練習モードではA機のみでクリアできます。

## 4人で遊ぶ

1. 全員が同じ公開URLをPCで開く。音声通話をつなぐか、同じ場所で声を掛け合う。
2. 1人が名前を入力して「ルームをつくる」を押す。
3. 「招待をコピー」でURLを共有。ほかの3人はURLを開いて「参加」、または6桁のコードを入力。
4. A機の下半身・上半身、B機の下半身・上半身の4枠が埋まったら、ホストが開始。
5. Q / Eで自分の機体の相棒へ定型メッセージも送れる。Escでマウスを解放。

参加時は空いている役割に自動配置されます。ロビーでは空席へ変更できます。ホスト以外の切断中はゲームが一時停止し、参加者が補充され4人そろうと再開します。再参加者は空席に入ります。**ホストが退出・再読み込みするとルームは終了**し、ホスト移譲やセーブはありません。ホストはゲームのタブを前面に保ってください。バックグラウンドではブラウザの描画頻度制限によりゲーム進行が遅くなります。

スマートフォンでも説明画面は閲覧できますが、ゲーム操作はPCのキーボード・マウス向けです。ゲーム内の音声通話、タッチ操作は未実装です。

## GitHub Pagesに公開

このリポジトリのルートがそのまま公開用ファイルです。`vendor/` を含めてGitHubへpushしてください。

1. GitHubのリポジトリで **Settings → Pages** を開く。
2. **Build and deployment → Source → Deploy from a branch** を選ぶ。
3. pushしたブランチ（例：`main`）と **`/ (root)`** を選び、Save。
4. デプロイ完了後、表示されるURLを4人で開く。

リポジトリが `Nag1t0727/fps_roleplay` の場合、通常の公開先は `https://nag1t0727.github.io/fps_roleplay/` です。これは想定URLであり、このプロトタイプ作成時点で公開されたことを意味しません。カスタムドメイン等によってURLは変わります。

参考：[GitHub Pages公式手順](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)

## P2P通信の仕組みと制約

HTMLとCSSだけでは通信できないため、JavaScriptのWebRTC DataChannelをPeerJS 1.5.5経由で使用しています。接続を取り持つシグナリングにはPeerJS Cloudを利用します。ゲームの計算はホストのブラウザが担当し、3人のブラウザと直接データを交換します。独自のゲームサーバーは不要ですが、完全に外部サーバー不要という意味ではありません。

- ホストがシミュレーションを進め、約20回/秒で状態を配信。各クライアントは入力を送信する。
- ホストは接続ごとの役割を管理し、他の役割の操作を適用しない。入力値を制限し、400ms以上更新がない入力は解除する。
- 壁・敵・コアなどの状態は各ブラウザへ配信し、役割に応じて描画を変える。改造クライアントへのチート対策や秘密情報の保護は対象外。
- 学校・企業のファイアウォールやNATの種類によってWebRTCが接続できない場合がある。別回線で試すか、別途TURNサーバーを用意する必要がある。TURN中継はこのプロトタイプに同梱していない。
- HTTPSのGitHub Pagesまたはlocalhostで実行。画面やマイクの権限は不要。音声通話は別サービスを利用する。
- PeerJSの配布ファイルは`vendor/`に同梱し、MITライセンスを添付。練習モードは通信サーバーを使わない。Google Fontsの取得に失敗しても代替フォントで動作。

独自のPeerServer / STUN / TURNを使う場合は、`index.html`のモジュール読み込みより前に `globalThis.SPLIT_SIGNAL_PEER_OPTIONS` を設定すると、PeerJSのコンストラクタオプションに渡されます。公開ファイルへ永続的な秘密鍵やTURNの長期認証情報を埋め込まないでください。

参考：[PeerJS接続方法](https://peerjs.com/client/getting-started)、[シグナリングとNAT/TURNの制約](https://peerjs.com/client/faq)

## ファイルと検証

| ファイル | 役割 |
| --- | --- |
| `index.html`, `style.css` | ロビー、役割選択、HUD、説明 |
| `src/engine.js` | マップ、移動、衝突、敵、射撃、救助、勝敗 |
| `src/renderer.js` | レイキャストによる一人称描画、役割別の表示 |
| `src/network.js` | PeerJS接続、席管理、入力検証、切断処理 |
| `src/app.js` | 操作、画面遷移、同期、ゲームループ |
| `vendor/` | ブラウザ用PeerJSとライセンス |

```sh
npm test
# ブラウザテストの開発依存を用意（Node.js 20以降を推奨）
npm ci
npm run test:e2e
```

ブラウザテストはGoogle Chromeを使用します。Chrome未導入の場合はインストールするか、`playwright.config.js`のchannelを環境に合わせて変更してください。4人通信のテストにはPeerJS Cloudへの接続とWebRTC通信が必要です。
